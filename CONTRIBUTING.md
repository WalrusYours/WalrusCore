# Contributing to WALRUS

Thank you for your interest in WALRUS.

## Pull requests are not accepted for now

WALRUS is developed as a thesis project, and the design is still moving. For now the project
does not accept code contributions: pull requests will be closed without review, even good
ones. This is not a judgement of the work; it keeps the design consistent while it settles.
This may change later, and this file will say so when it does.

You are still free to use, modify and redistribute the code under the terms of the
[Apache License 2.0](LICENSE), including keeping the [NOTICE](NOTICE) with any copy.

## Issues are welcome

Please use the issue tracker for:

- **Bug reports.** Say what you did, what you expected and what happened. Include the WALRUS
  version (`GET /health` returns it), the request and the response, the error `code` and
  `message`, and the smallest schema that shows the problem.
- **Feature requests.** Describe the problem you want solved before the solution you have in
  mind: what your platform does, what you could not express in the schema or the API, and
  why. A short example schema or request helps more than a long description.
- **Questions about the API or the schema**, if the [README](readme.md) and the
  [schema docs](docs/schema/README.md) do not answer them.

Before opening an issue, search the existing ones. If your case is already there, add what
is new to that issue instead of opening another.

Please do not put admin keys, tenant data or other secrets in an issue. A schema or request
example should use made-up data.

## Security problems

If you found a vulnerability, do not open a public issue. Contact the author privately
through the details on the [project website](https://walrusyours.github.io), and give them a
reasonable time to fix it before you share it.

## Conduct

Be respectful and keep to the point. Issues that are abusive or off topic will be closed.
